---
title: Memory Management
description: How IngestX prevents out-of-memory crashes
---

Browser memory is finite. When processing very large spreadsheets, accumulating all data in JavaScript object structures can easily crash the page, forcing the browser to terminate the tab.

IngestX employs chunk-based parsing to mitigate this, but it requires correct configuration to be completely safe.

## The `collectResults` Danger

By default, `collectResults` is `false`.

If you set `collectResults: true` in your ingestion options, IngestX retains every parsed row in memory, pushing them into the `validRows` and `invalidRows` arrays so that you can access them via `result.data` at the end of the run.

**This creates O(N) memory growth.**

For a 10,000 row CSV, this is completely harmless. For a 2,000,000 row CSV, accumulating the rows in memory will likely exceed V8's heap limit and crash the tab.

## Safe Handling for Massive Files

To process massive files safely, you must keep `collectResults: false` and instead subscribe to the `onChunkProcessed` callback.

```typescript
ingest({
  file,
  columns,
  collectResults: false,
  onChunkProcessed: async (chunk) => {
    // This callback is invoked every time a batch of rows completes validation.
    
    // We can confidently upload this chunk to our server over HTTP.
    await postToMyBackend("/api/upload", chunk.output.validRows);

    // After this callback finishes, the chunk is discarded from memory!
  }
})
```

Because `collectResults: false` prevents IngestX from retaining the rows internally, the V8 garbage collector will smoothly discard each chunk of rows from memory after your `onChunkProcessed` callback completes.

This enables **infinitely scalable** parsing, achieving O(1) flat memory consumption (only bound by the file chunk size itself).

## The Collection Limit Safety Net

If you absolutely must use `collectResults: true`, you can protect your users from malicious or accidental massive uploads by defining a `maxCollectedRows` ceiling.

```typescript
ingest({
  file,
  columns,
  collectResults: true,
  maxCollectedRows: 50000 
})
```

If the parser encounters row number 50,001, the ingestion is instantly aborted, and an `IngestionErrorType.COLLECTION_LIMIT_EXCEEDED` error is thrown, sparing the browser from crashing.
